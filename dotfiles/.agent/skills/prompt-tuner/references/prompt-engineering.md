# プロンプトの診断リファレンス

観測した失敗から確認箇所を選ぶ。同じ症状でも、指示、入力資料、モデルの設定、ツールや表示処理で原因が異なる。表の確認結果を根拠に修正し、当てはまらない処方を一括適用しない。

## 症状から確認する

| 観測した症状 | 先に確認すること | 確認後の修正候補 |
|---|---|---|
| 作業が途中で止まる | 未承認の操作や必須入力待ちか、skill が不要な承認待ちを作っているか | 許可済みの作業の完了条件と、判断が必要な停止条件を分ける |
| 進捗が見えない | モデルの更新をクライアントが受信・表示しているか、進捗を禁止する指示があるか | 表示側の問題は別に扱い、矛盾する指示を除いて更新のタイミングと内容を指定する |
| 取得処理が逐次になる | 呼び出し間にデータ依存があるか、runner が並列実行を扱えるか | 独立した読み取りをまとめ、結果に依存する操作は後で行うよう指定する |
| 古い情報や未知の名称を断定する | 対象資料・検索ツールが使えるか、名称の補正を促す指示があるか | ユーザーの表記を含めて公式情報を取得し、確認できない事実を断定しないようにする |
| 文章の長さや体裁が用途に合わない | 指定形式、必須情報、旧モデル向けの一律な書式抑制があるか | 必須情報を保ち、比較や手順など読みやすくなる場面でリストを使うよう指定する |
| 要約に原文が混ざる | 引用と要約を区別できる例や出典があるか | 自分の言葉による要約と、明示した短い引用を区別する完成例を示す |
| 出力形式が安定しない | 指示と例の不一致、対象 API のスキーマ機能の有無 | 必須フィールドと完成例を整合させる。API 設定の変更はプロンプト変更と別に評価する |
| 正確性が不足する | 根拠資料の欠落、誤った例、制約の矛盾、ツール失敗がないか | 原因を修正し、必要な入力・確認方法を明示する。思考を長くする指示だけで代用しない |
| 遅い、または長い成果物が途切れる | reasoning / effort、出力上限、終了理由、同じ取得や生成の反復 | 重複を削る。設定比較が依頼範囲なら、品質と完了率を保てる条件を別実験で比較する |

## モデル別のガイドを使う境界

以下は 2026-09-05 に確認した公式資料。適用時には対象モデルと該当節を再確認する。

- [OpenAI model guidance](https://developers.openai.com/api/docs/guides/latest-model): skill の指示とユーザーの依頼の衝突、自律実行、文章、委譲、検証範囲の調整を確認する。
- [Claude Fable 5.1 のプロンプティング](https://platform.claude.com/docs/ja/build-with-claude/prompt-engineering/prompting-claude-fable-5-1): 観測した症状に対応する節から確認する。進捗の表示、検索、会話履歴、長い出力などは実行環境の確認も必要になる。

モデル間で同じ effort 名が同じ計算量を表すとは限らない。API 固有のパラメータ、ベータ機能、履歴管理は実行コードの責務として扱い、共通の `AGENTS.md` や別 provider にそのまま移植しない。モデル・runner の切替や安全性の制約緩和を、プロンプト改善の一般処方にしない。
